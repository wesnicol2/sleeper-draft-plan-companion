Draft Companion — planning notes

PRODUCT GOAL
- Auto-updating second-screen UI for a live Sleeper draft.
- Reduce draft-time interaction: roster state, needs, player availability, and
  decision context should already be visible when the user looks at the board.
- Keep ranking and recommendation signals separate and explainable rather than
  hiding every preference inside one score.

CURRENT IMPLEMENTED FOUNDATION
- Tracks Sleeper draft state, the user's roster, snake-draft timing, and the
  configured checkpoint plan.
- Normal board shows every active, undrafted QB/RB/WR/TE known to Sleeper; there
  is no fixed 32-player horizon.
- Player ordering uses repository static ADP first, Sleeper search_rank as an
  explicit fallback, then a deterministic unranked tail so deep players are not
  dropped just because ranking data is missing.
- Cost of waiting compares canonical static ADP now vs the same-position fallback
  at the user's next projected pick. This is ordinal ADP deterioration, not WAR.
- Positional strength uses Consensus ADP market value, league starter/FLEX
  structure, strategic beta targets, and diminishing bench-depth credit.
- Checkpoint need remains count-based and sorts columns before positional
  strength; neither checkpoint need nor strength colors player cards.

REPOSITORY-BACKED PERSONAL PREFERENCES
- resources/player-preferences.csv owns Starred and Do Not Draft.
- resources/general-preferences.csv owns positional-strength alpha/beta values.
- resources/dart-throws.csv owns the ordered late-draft Dart Throw list and the
  user's rationale for each candidate.
- These settings are intentionally not editable in the live UI. Repository state
  is the source of truth so browsers, Test, Production, and recreated containers
  remain consistent for a deployed commit.

CONTEXTUAL PLAYER SIGNALS
- Positive: checkpoint LEAN, QB + WR/TE passing STACK, configured TOP 5 OFF.
- Negative: configured BOTTOM 5 OFF, same-position bye conflicts, and same-team
  concentration outside a passing stack.
- Same-team overlap is position-sensitive:
  - same position = TEAM×2, negative color weight 2;
  - different position = TEAM, negative color weight 1;
  - QB + WR/TE = positive STACK;
  - QB + RB = neutral and does not count toward card color/team load.
- Signals are presentation-only. They should remain visible/explainable and not
  silently rewrite canonical rank.

DART THROW MODE
- Unlock only after QB, RB, WR, and TE positional strength are each >= 1.00.
- Then expose a Normal / DART THROW view toggle.
- Normal mode stays unchanged.
- Dart Throw mode shows only currently available players from
  resources/dart-throws.csv, in the exact static order defined there.
- Each dart card remains the same underlying card with its normal strength,
  contextual color/signals, Starred and Do Not Draft treatment, plus the
  repository rationale explaining the upside thesis.
- Dart candidates do not need canonical ADP coverage; name+position matching to
  the Sleeper player pool is sufficient.
- ADP fallback rails / next-pick geometry are hidden while the board is in a
  deliberately non-ADP Dart Throw order.
- The rationale is personal scouting context, not verified news or a numeric
  recommendation input.

NEXT MODELING WORK
- Validate Cost of waiting and positional-strength behavior with real/historical
  drafts before adding urgency buckets or a unified recommendation score.
- Consider WAR/replacement-value only after the underlying scale and replacement
  definition are defensible.
- Add probabilistic player availability only when historical draft data supports
  it; do not replace a transparent deterministic rule with arbitrary confidence.
- Explore a separate ceiling/breakout model for bench players. Positional
  strength's diminishing bench-depth credit is not intended to predict upside.
- Preserve individual signals (offensive environment, injury opportunity,
  handcuff value, coaching/team changes) even if a future aggregate score is
  added, so surprising recommendations stay inspectable.

VALIDATION PRIORITIES
- Real Sleeper mock drafts across early RB-heavy, WR-heavy, late-RB, early QB/TE,
  and delayed QB/TE builds.
- Confirm the full uncapped board remains responsive while candidate strength is
  calculated for every available player.
- Confirm same-position team overlap is visibly stronger than cross-position
  overlap and QB/RB same-team pairs are neutral.
- Confirm repository Starred/Do Not Draft/model settings are identical in Test
  and Production after promotion and cannot be changed from the UI.
- Confirm Dart Throw toggle appears exactly when the fourth tracked position
  reaches 1.00, preserves exact CSV order, and shows rationale for deep players.

STRETCH GOALS
- Season-long player projections from odds data.
- Defensible Wins Above Replacement for every player.
- Historical replay harness for draft decision quality.
- Additional repository-backed player notes/categories if they remain useful
  without introducing draft-time editing overhead.

INTERFACES
- Sleeper API: draft state, picks, player metadata, teams, draft order.
- Repository resources: ADP, personal preferences, strength parameters, Dart
  Throw list/rationale, and draft-plan configuration.
