- Draft companion
    - Will keep up with draft and suggest players at each point based on draft plan (draft plan should be configured in config files only)
    - Auto update with top suggestions for each round depending on team construction + my preferences
    
            

Minimum viable product: A auto updating UI (no interaction needed from user) which shows top picks based on draft plan. Players should be highlighted with different colors based on how many draft plan criteria they have

NEXT STEPS: 
- Improve player highlighting and decision context
    - Add team synergy signals:
        - Highlight WRs/TEs whose QB is already on the roster.
        - Highlight QBs whose WR/TE is already on the roster.
    - Add bye-week signals:
        - Negatively highlight players whose bye week conflicts with an existing player at the same position.
    - Keep each signal separate and explainable rather than incorporating them into ranking yet.
- Model positional strength
    - In the draft-plan, Replace simple player counts with weighted positional strength. We should be looking for strength at each position, not plain counts of players
    - Weight drafted players by round, initially using an inverse-square curve (1 / round²).
    - Combine positional strength with remaining positional needs to determine which positions are actually scarce.
    - Eventually replace round-based weighting with the individual player's WAR.
- Build a flexible player-ranking system
    - Give every player a canonical rank and support multiple ranking sources.
    - Initially support the static ADP CSV, with the ability to manually override ranks.
    - Later support alternative ranking sets such as ADP, external rankings, and WAR.
        - Define player value above replacement
        - Establish a positional definition of replacement value.
        - Calculate value above replacement for each player.
    - Use the value gaps to identify meaningful positional drop-offs and “dead zones.”
    - Identify the last strong option at each position before a significant drop-off.
- Add later-round alternatives
- Show the best remaining players at each position outside the current checkpoint.
- Include their rank/value and likely draft range.
- Use this to answer “Can I safely wait?” before drafting a position early.
- Base this increasingly on WAR and positional drop-offs rather than arbitrary round thresholds.
- Build a draft-value/recommendation model
- Combine ranking, positional need, positional strength, WAR, drop-off risk, and later-round alternatives.
- Add contextual signals such as:
    - team/offensive environment
    - handcuff value
    - coaching changes
    - teammate changes
    - starter/injury opportunity
    - bye-week fit
    - roster synergy
    - Keep individual factors visible so recommendations remain explainable.
- Integrate higher-fidelity rankings
- Validate the model against real drafts
    - Replay historical draft scenarios.
    - Test whether the system correctly identifies scarcity, safe waits, drop-offs, and players who should be taken before a positional cliff.
    - Tune heuristics only after observing where the model produces bad recommendations.

- Player notes / snippets
    - When I hear something about a player (podcast, beat writer, injury chatter), log it against that player
    - A player with notes shows an icon on their card so it is obvious at a glance which players I have intel on
    - Clicking the icon opens that player's notes
    - Notes persist across sessions and are mine, not shared
    - Open questions to settle before building:
        - Are notes free text only, or also tagged (injury / role / coaching / sleeper)?
        - Can a note be added mid-draft, or is logging a pre-draft activity only?
          (the app is otherwise strictly no-interaction during a draft)
        - Do notes affect ranking or highlighting at all, or are they purely informational?
